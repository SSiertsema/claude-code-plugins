# ISO/IEC 25010:2023 + 25023 — Assessment Reference

The authoritative mapping for this skill. For each of the **9 characteristics**, this lists its **sub-characteristics**, the **static evidence** to inspect, and the **ISO/IEC 25023-style measure(s)** with a derivability tag:

- **S** — statically derivable from the codebase
- **P** — partially derivable (proxy from static evidence; full value needs runtime data)
- **R** — runtime-only (mark "not statically measurable" unless `--metrics` supplied)

Rate each applicable sub-characteristic **Pass / Partial / Fail** with `file:line` evidence. Mark **N/A** only when genuinely irrelevant to the target (record in `na`, exclude from scoring).

---

## 1. Functional Suitability

| Sub-characteristic | Static evidence to inspect | 25023-style measure (tag) |
|---|---|---|
| Functional completeness | Requirements/specs/issues vs implemented features; TODO/stub markers | Functional coverage = 1 − (missing functions ÷ specified functions) (P) |
| Functional correctness | Test assertions, known-bug trackers, defect comments | Functional correctness = 1 − (incorrect functions ÷ evaluated functions) (P) |
| Functional appropriateness | Feature scope vs stated goal; dead/extraneous code | Functional appropriateness of tasks (P) |

## 2. Performance Efficiency

| Sub-characteristic | Static evidence | Measure (tag) |
|---|---|---|
| Time behaviour | Hot paths, algorithmic complexity, N+1 queries, render-time work, missing memoization | Mean response time (R); static complexity hotspots (S) |
| Resource utilization | Unbounded caches, leaked listeners/intervals/handles, large in-memory structures | Mean resource utilization (R); cleanup-on-teardown presence (S) |
| Capacity | Pagination/streaming/batching for large data; fixed-size limits | Capacity headroom (R); bounded-collection presence (S) |

## 3. Compatibility

| Sub-characteristic | Static evidence | Measure (tag) |
|---|---|---|

| Interoperability | Documented/typed public contracts, schema/versioned APIs, standard formats | Data formats exchangeability = exchangeable formats ÷ total (S) |

## 4. Interaction Capability *(was Usability — target WCAG 2.2 AA)*

| Sub-characteristic | Static evidence | Measure (tag) |
|---|---|---|
| Appropriateness recognizability | Clear labels/affordances on UI controls | Description completeness (S) |
| Learnability | Consistent patterns/naming; onboarding docs | User guidance completeness (S) |
| Operability | Keyboard operability, focus order, control semantics | Operational consistency (S) |
| User error protection | Input validation, guarded destructive actions, confirmations | User error protection = protected actions ÷ error-prone actions (S) |
| User engagement | Loading/empty/success/error feedback states present | UI appearance customizability / feedback presence (P) |

| Self-descriptiveness | Semantic HTML, accessible names, self-explanatory UI | Self-descriptiveness (S) |

*N/A for non-UI codebases (libraries, services) — record and exclude.*

## 5. Reliability

| Sub-characteristic | Static evidence | Measure (tag) |
|---|---|---|
| Faultlessness *(was Maturity)* | Edge/boundary test coverage; defensive code | Mean time between failures (R); edge-case test density (S) |
| Availability | SSR/hydration safety, startup/health checks, no fatal init paths | Availability = uptime ÷ (uptime + downtime) (R); health-check presence (S) |
| Fault tolerance | try/catch coverage, error refs handled, circuit breakers, retries | Failure avoidance = handled fault patterns ÷ total (P) |
| Recoverability | Retry UX/back-off, graceful fallback, transactional rollback, backups | Mean recovery time (R); recovery-path presence (S) |

## 6. Security

| Sub-characteristic | Static evidence | Measure (tag) |
|---|---|---|
| Confidentiality | Hard-coded secrets/tokens, sensitive data in logs, over-broad exposure | Access controllability = controlled accesses ÷ required (P) |
| Integrity | XSS sinks (`v-html`/`innerHTML`), SQL/command injection, missing input sanitization, CSRF | Data integrity = protected items ÷ items requiring protection (P) |
| Non-repudiation | Audit logging of state-changing actions | Action audit trail completeness (P); *N/A for pure display* |
| Accountability | Attribution of user actions to identities | User audit trail completeness (P); *N/A for pure display* |
| Authenticity | Auth guards/middleware on protected routes/resources; token validation | Authentication mechanism strength (P) |
| Resistance *(new 2023)* | Input hardening, rate-limit handling, dependency CVEs (SCA), unsafe deserialization | Known-vulnerability exposure = vulnerable deps ÷ total deps (S) |

| Sub-characteristic | Static evidence | Measure (tag) |
|---|---|---|
| Operational constraint | Destructive actions constrained/confirmed; rate/quota limits | Operational constraint coverage (S) |

---

## Notes on 25023 measures

- Measure names follow the **spirit** of ISO/IEC 25023 quality measure elements; exact clause numbering is not reproduced. Report the value and its **basis** (how it was derived).
- For **P/R** measures without supplied metrics, report the static proxy if one exists (and label it a proxy), otherwise mark **"not statically measurable"** in the Limitations section. Never fabricate a numeric value.
- When `--metrics` provides real runtime data, upgrade the relevant P/R measures to computed values and note the source.
